# 清丰工作模式

选择一个主模式。输出深度与用户问题匹配，不为填满模板扩张研究。涉及数值仓位或价格区间时，研究准出必须先于交易计划。

## A. 快速筛选

1. 用一句话说明谁付钱、买什么、如何收费；
2. 检查证券主体、资产归属、数据期间和来源层级；
3. 扫描可得的长期收入、利润、现金、债务、应收存货和股本趋势；
4. 找出最大机制未知、结构性红线和最小补证集；
5. 选择 `OUT_OF_SCOPE` / `REJECT` / `RESEARCH_MORE` / `WATCHLIST`。

完成标准：至少三个继续/停止研究理由，一份最小补证清单，不输出买入结论、数值仓位或伪精确估值。

## B. 深度公司研究

1. 完成能力圈与信息丰富度判断；
2. 构建价值创造链和客户—产品—渠道—交付—经济性—再投资画布；
3. 把核心经营主张逐条写成证伪链；
4. 检查行业利润池、替代品、管理层“承诺—资源—结果—纠错”和治理；
5. 用生存—质量—复利三层财务痕迹验证；
6. 独立建立最强多方和最强空方；
7. 数据准出后完成目标回报门槛、反向估值、三情景和敏感性；
8. 与现金、已有持仓和候选项比较机会成本；
9. 输出五闸门、三轴、总状态和复核规则。

数据不足时允许完成定性熊/基准/牛路径，但不得补造数值目标价。当前价格、完全稀释股本、现金流或价值桥缺失时，赔率轴为 `UNPRICED`，总状态为 `RESEARCH_MORE`。

## C. 估值/重定价

本模式要求近期业务因果与财务验证已准出，否则先补研究。

1. 确认当前价格、市值、完全稀释股本、会计与交易币种；
2. 让用户给定的必要回报率成为主输入；未给定时展示多档门槛，不替用户选唯一值；
3. 用反向模型计算达到各档目标回报需要的业绩；
4. 构建有完整经营故事的熊/基准/牛；
5. 计算满足目标回报的最高可接受价格 `P_max`；
6. 展示年化回报、损失区间、关键敏感性和估值脆弱点；
7. 判断 `ATTRACTIVE` / `FAIR` / `UNFAVORABLE` / `UNPRICED`。

完成标准：不用历史均值代替目标回报门槛；年化回报已处理分红、回购、稀释和净债务变化。没有 `P_max` 不进入数值交易计划。

## D. 买入前检查

买前检查不替代深研。依次闯过生意、证据、复利、赔率、组合五闸门。

必须分别回答：

- 好公司？
- 好价格？
- 适合当前组合？
- 买入理由对应的三个失效条件是什么？
- 更好替代项是什么？

缺完整组合、风险预算、现金需求、税务或流动性信息时，组合轴为 `UNKNOWN`，追加 `NO_ACTION`，不输出个人化仓位。五闸门通过后，只有用户要求位置或批次时才转入 G 模式。

## E. 持仓论文与计划跟踪

1. 找到带日期的原始买入论文、估值、组合政策、交易计划和失效条件；
2. 先忽略成本价和涨跌，将新事实映射到原论文变量；
3. 标记改善/未变/恶化/未知，并分为噪声/周期/执行偏差/结构性变化；
4. 重算每股价值、目标回报、目标仓位和剩余风险预算；
5. 更新研究、论文和计划三个状态；
6. 将每个预警/触发器标记为未触发、预警、已触发或已处理；
7. 按 [position-monitoring.md](position-monitoring.md) 输出暂停、补证、战术减仓、战略减仓或退出草案；
8. 更新版本日志和下次时间/事件触发器。

原论文不可得时，不事后伪造历史。建立当日基线论文，总状态设为 `RESEARCH_MORE`；在研究重新准出前不形成数值加仓计划。

## F. 组合构建/复盘

1. 读取 [portfolio-policy.md](portfolio-policy.md)，标记政策参数来自用户还是清丰默认参考；
2. 将每只持仓视为虚拟集团的子公司，分开经营归属值和市值风险暴露；
3. 穿透客户、产业链、地区/币种、利率、政策、技术、估值和治理的重复暴露；
4. 建立至少两个与主要暴露匹配的压力情景；
5. 比较论文强度、赔率、下行损失、共同暴露、流动性和替代机会；
6. 为每只持仓计算目标权重上限、实际偏离和资金来源；
7. 仅在容忍带或硬约束触发时形成再平衡草案；
8. 输出组合状态和非执行性动作条件。

缺持仓数量/权重、价格、组合净值、现金需求、税务或期限时，只输出定性风险图和待补数据，状态 `UNKNOWN + NO_ACTION`。

## G. 建仓/加减仓交易计划

1. 验证公司 `PASS`、赔率已准出、组合 `FIT`，否则输出观察条件后停止；
2. 用 [portfolio-policy.md](portfolio-policy.md) 计算目标仓位上限和资金来源；
3. 用估值取得 `P_max`，再读取 [technical-and-chip-analysis.md](technical-and-chip-analysis.md) 形成价格区域；
4. 用 [trade-plan.md](trade-plan.md) 生成试仓/确认/完成或减仓/退出批次；
5. 计算每批数量、金额、权重、费用、预计损失和剩余预算；
6. 检查最小交易单位、流动性、公司行动、跳空/停牌和数据时效；
7. 写明触发、取消、重算、有效期和人工确认条件；
8. 输出 `DRAFT · REQUIRES_USER_APPROVAL · NOT_AN_ORDER`。

完成标准：批次之和、现金、权重、损失预算、共同暴露和费用数学一致；技术/筹码未越过基本面、估值或组合边界；没有调用交易接口。

## H. 持续跟踪计划

1. 建立论文、估值、组合、执行四类触发器及当前状态；
2. 设定每周、每月、财报后和重大事件复核清单；
3. 创建目标/实际权重、核心/交易仓、风险余额和计划到期面板；
4. 用户没有明确要求自动跟踪时，只输出清单和下次日期；
5. 用户明确要求持续跟踪时，才可使用产品提供的只读提醒或自动化；
6. 每次更新只形成新版本研究与计划，不自动报单。

完成标准：所有触发器有来源、状态、动作、处理结果和下次证据，且用户能区分事实变化与价格噪声。
