# 公开发布与脱敏

仅在用户要求公众号、公开报告、媒体稿或政治敏感脱敏时读取。内部证据底稿与公开稿分开保存，公开稿的脱敏不能反向污染原始统计。

## 1. 政治敏感处理

- 用户要求不出现领导人姓名时，标题、正文、注释、来源链接文字、图片文字、SVG、HTML 元数据和代码注释均不出现全名。
- 只有语义确实需要区分人物时，使用用户允许的大写首字母；不需要时直接删除人物维度。
- 来源原网页标题含姓名时，把可见链接文字改为“起草说明”“相关负责人说明”等中性描述，URL 保持原始链接。
- 公开稿只陈述可由文本支持的结构、制度、预算和项目事实，不从姓名次数推断权力、动机、社会状态或政策效果。

完成后从内部人物表生成本次稿件的禁用词清单，对 Markdown、HTML、SVG 文本、文件名和元数据执行全文扫描；命中为零才交付。

## 2. 通俗化顺序

面向普通读者时按以下叙事：

1. 用具体场景说明“数热词”的直觉；
2. 用篇章升降解释真正的结构信号；
3. 用预算和项目说明方向是否进入执行层；
4. 用一个“收入增长但现金流变差”或“需求增长但价格下跌”的反例解释投资风险；
5. 用“政策—行业—公司—估值”四层问题收束。

避免大段政策原文、政治化形容词和无法证实的动机判断。行业术语第一次出现时用一句话解释。

## 3. 数字核查

初稿完成后逐项建立数字清单，回查文件版本、报告期、单位和来源。现在时数据标明截止日期；预算授权、项目下达、已拨付、已开工与已形成收入使用不同措辞。

无法核实的精确数字改为方向性表达或删除。跨来源口径冲突在公开稿中简化前，内部底稿必须保留差异和处理理由。

## 4. 发布边界

公开投资内容注明研究方法和数据来源，不构成投资建议。公司样本只证明方法时可泛化为行业样本；若保留公司名，必须同时给出估值与风险，避免单向宣传。

若交付 HTML，确保正文样式内联、图片/SVG 不含敏感姓名，并在发布平台实际粘贴前保留一次人工预览步骤。
